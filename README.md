# POM Studio — конструктор модулей

Отдельное приложение для сборки подключаемых модулей площадки. Не является
частью игровой платформы: не подключает `core/`, не ходит в API и не знает
про комнаты, ники и живые жетоны. Связь с площадкой — только
экспортированный файл модуля.

## Запуск

Статический сервер из папки `studio/`:

```
python -m http.server 8771
```

Открыть `http://127.0.0.1:8771/`. Подойдёт любой статический сервер; сборка
не нужна. Площадка этот адрес не отдаёт и не зависит от него.

## Что уже работает

- демо-проект и пустой проект;
- вкладки правой панели: добавление, удаление, порядок, название, иконка;
- секции и компоненты на сетке 12 колонок: 11 типов;
- перетаскивание, изменение размера, инспектор свойств;
- мультивыделение (Ctrl/Cmd или Shift + клик), копирование, вставка,
  дублирование и удаление группы компонентов;
- перемещение выбранных компонентов стрелками (Shift — на 5 клеток);
- замок и скрытие компонентов, пометка «только для мастера»;
- предупреждение о пересечении компонентов на холсте и в инспекторе;
- дублирование секций и вкладок;
- отмена и повтор (Ctrl+Z / Ctrl+Shift+Z), история с объединением
  быстрых правок;
- предпросмотр панели и чата в модальном окне: ширина, масштаб,
  режим игрока/мастера, тестовые данные;
- скрытые и мастерские компоненты не попадают в предпросмотр игрока;
- библиотеки: вкладки-списки с перетаскиванием, схема характеристик
  и таблица предметов;
- добавление предметов вручную, поиск, дублирование и удаление;
- импорт и экспорт Excel по схеме списка, скачивание пустого шаблона;
- листы персонажа: плавающее окно с вкладками, секциями и компонентами;
- поле для картинки, длинный текст, селекторы и кнопки на сетке 12 колонок;
- компонент «Предмет из библиотеки»: выпадающий список предметов и их полей;
- предпросмотр листа как окна игрока;
- логика: дерево компонентов по поверхностям и вкладкам, макросы кнопок и чисел;
- шаги «Спросить», «Бросок», «Присвоить», «Изменить число», «Изменить текст»,
  «Если» и «В чат»;
- вставка числовых полей в формулы и читаемый предпросмотр ссылок;
- проверка проекта перед сохранением: ошибки, предупреждения и ссылки
  на проблемные места;
- сохранение проекта в папку: `system.json`, `README.md`;
- открытие папки и выгрузка в новую папку;
- fallback: скачивание `system.json`, если браузер не умеет писать в папку.

Проект сохраняется в папку и открывается обратно. Экспорт отдельной
библиотеки в Excel тоже работает.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl/Cmd + S` | сохранить проект |
| `Ctrl/Cmd + Z` | отменить |
| `Ctrl/Cmd + Shift + Z`, `Ctrl + Y` | повторить |
| `Ctrl/Cmd + A` | выбрать все видимые компоненты вкладки |
| `Ctrl/Cmd + C`, `Ctrl/Cmd + X` | копировать / вырезать выбранные компоненты |
| `Ctrl/Cmd + V` | вставить копии со сдвигом |
| `Ctrl/Cmd + D` | дублировать выбранные компоненты |
| `Delete`, `Backspace` | удалить выбранные компоненты или секцию |
| Стрелки | сдвинуть выбранные компоненты на 1 клетку |
| `Shift + стрелки` | сдвинуть на 5 клеток |
| `Escape` | снять выделение / закрыть предпросмотр или инспектор |

Заблокированные компоненты нельзя двигать, удалять и менять размер;
их можно выделять и снимать замок через бейдж на холсте.

## Библиотеки

Раздел «Библиотеки» — это списки предметов по вкладкам. Каждая вкладка —
один список: «Оружие», «Броня», «Заклинания».

1. Создайте список: название, иконка, категория.
2. На вкладке «Схема» добавьте характеристики: подпись, тип, единицу,
   обязательность, значение по умолчанию и варианты для списка.
3. На вкладке «Предметы» заполните строки вручную или загрузите из Excel.
4. Порядок вкладок меняется перетаскиванием.

Экспорт создаёт `.xlsx` с листом данных, листом «Схема» и листом
«Инструкция». Импорт читает первый лист, проверяет типы и показывает
предпросмотр: новые, обновления и ошибки. По умолчанию предметы
добавляются и обновляются по названию; отсутствующие в файле записи
не удаляются.

SheetJS лежит в `vendor/xlsx/` и используется только конструктором.
Площадка его не загружает. Лицензия — в `vendor/xlsx/LICENSE`.

## Листы персонажа

Раздел «Листы персонажа» собирает окно, а не игровые механики.

1. Создайте лист: название, иконка, ширина и высота окна.
2. Добавьте вкладки; порядок вкладок меняется в инспекторе.
3. На холсте вкладки расставьте компоненты: подписи, селекторы, кнопки,
   поле для картинки, длинный текст и «Предмет из библиотеки».
4. «Предпросмотр» открывает окно так, как его увидит игрок.

Компоненты используют ту же сетку 12 колонок, drag & drop и инспектор,
что и правая панель. Пока это оболочка; привязки полей к данным и хранение
экземпляров — следующие этапы. Макросы кнопок собираются в разделе «Логика».

## Логика

Раздел «Логика» — конструктор макросов кнопок и числовых полей.

Слева дерево: «Лист персонажа» и «Боковая панель», внутри — вкладки и группы
«Кнопки», «Числа», «Заголовки», «Текстовые поля».

- Нажатие на кнопку выбирает её макрос; при первом выборе создаётся пустой.
- Нажатие на число вставляет `{{id}}` в последнее поле формулы; под полем
  видно читаемый предпросмотр.
- ⚡ у числа создаёт макрос на изменение этого числа.
- «Изменить текст» и клик по заголовку или текстовому полю задают цель
  для смены текста.
- Поля предмета из библиотеки вставляются как `{{componentId.fieldId}}`;
  значение берётся у выбранного предмета в компоненте листа.

Шаги: «Спросить» (попап), «Бросок», «Присвоить», «Изменить число»,
«Изменить текст», «Если» с ветками «Тогда/Иначе», «В чат». В формулах
используются ссылки на компоненты, `@last.total` и `@ask.key`.
Предупреждения показываются прямо в шагах, кнопка «Проверить» собирает их
по всем макросам.

В демо-листе есть HP и поле «Состояние» — на них собран пример условия
«HP ниже порога → текст “Ранен”».

Пока это конструктор данных: исполнение макросов в игровом клиенте —
следующий этап. Полноценный Blockly-холст можно наложить на эту же модель
шагов позже.

## Сохранение

«Сохранить» пишет `system.json` и `README.md` в выбранной папке.
«Выгрузить» выбирает новую папку. «Открыть папку» читает `system.json`
и восстанавливает проект.

Нужен Chrome или Edge на `localhost` (File System Access API). Если запись
в папку недоступна, «Сохранить» и «Выгрузить» скачивают `system.json`,
а «Открыть папку» открывает файл.

## Проверка, схема и тесты

Раздел «Публикация» запускает `POM_EDITOR.validateProject` и показывает
ошибки и предупреждения: метаданные, повторяющиеся ID, геометрию и
пересечения, типы компонентов и полей, ссылки макросов на компоненты,
пустые формулы и условия, значения предметов библиотек.

Формат описан JSON-схемой `schema/system.schema.json`
(draft 2020-12). Схема проверяет структуру; смысловые ссылки, пересечения
и миграции проверяет редактор.

Тесты модели, миграций, клонирования и валидатора запускаются без npm:

```
node --test studio/tests/studio.test.js
```

Миграции формата лежат в `POM_EDITOR.MIGRATIONS` в `js/project.js`:
ключ — исходная версия, значение — функция `data → data`. При открытии
модуля `normalizeProject` копирует вход, применяет недостающие миграции
и только потом заполняет пропущенные поля.

## Граница с площадкой

- конструктор создаёт и экспортирует модуль;
- площадка загружает `system.json` и строит панель, листы и библиотеки;
- макросы в площадке пока не исполняются;
- общий контракт — формат модуля, а не код, сервер или runtime;
- Blockly и редактор живут только здесь; в площадку уходит
  скомпилированное описание логики, а не workspace и не библиотека блоков.

## Целевой формат модуля

```
my-system/
  system.json      метаданные, панель, листы, библиотеки, макросы
  README.md        краткое описание модуля
```

`system.json` версионируется (`formatVersion`). Конструктор проверяет
совместимость при экспорте, площадка — при загрузке. Отдельные файлы
`sheets/` и `libraries/` можно добавить позже, если понадобится разбиение.

## Модель

- **Жетон** на карте — миниатюра: имя, позиция, владелец, скрытность,
  события. Игровых данных в нём нет.
- **Шаблон листа** создаётся в конструкторе: секции, поля, пути,
  вычисляемые значения, скрипты.
- **Экземпляр листа** появляется в игре: данные персонажа, владелец,
  необязательная привязка `tokenId`.
- События жетона (выбор, перемещение, смена поля) рантайм передаёт в
  скрипты листа; результат уходит в панель и чат через площадку.

## Этапы

1. Отдельное приложение и формат модуля.
2. Конструктор шаблона листа: поля, пути, значения по умолчанию,
   вычисляемые поля.
3. Блочная логика: Blockly в конструкторе, компиляция в компактный AST,
   валидатор и предпросмотр на мок-платформе.
4. Загрузчик модулей — готов; хранилище экземпляров листов — следующий шаг.
5. «Песочница» как приёмка: собрать модуль без кода, экспортировать,
   загрузить и сыграть.
